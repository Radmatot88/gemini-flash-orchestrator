# 🤖 Gemini Flash Orchestrator Skill v2.0

Этот скилл предназначен для подготовки, генерации и развертывания **параллельных** мультиагентных роев на базе Gemini Flash в **любом** проекте.

## 🗺 Как работать со скиллом (Инструкция для ИИ)

🚫 **ГЛАВНЫЙ ЗАПРЕТ СКИЛЛА:** Твоя задача в этом скилле — ТОЛЬКО спроектировать архитектуру и сгенерировать промпты. НИ ПРИ КАКИХ ОБСТОЯТЕЛЬСТВАХ не пытайся сам писать код проекта, менять файлы (кроме `ai_manifests/` и `scripts/prompts/`) или реализовывать фичи! Если пользователь пишет *"Приступай"*, *"Делай"* или *"Начинай"*, это означает команду на **генерацию и запуск роя**, а не на фактическое программирование руками.

Когда пользователь запрашивает настройку субагентов, спринта субагентов, просит "собрать агентов", "запусти рой", "запусти по манифесту" или скилл вызывается через **Chained Handoff из `session-kontext`**, ты **ОБЯЗАН** определить ВЕТКУ ВХОДА и следовать соответствующему пайплайну:

---

### Шаг 0: Определение ветки входа

Проверь условия и выбери ОДНУ ветку:

| Условие | Ветка |
|---------|-------|
| Пользователь передал Swarm Manifest (`.md` с блоками `PROMPT_NN`) | **Ветка 1: Manifest Mode** |
| Вызов из `session-kontext` (свежий kontext-файл) | **Ветка 2: Chained Handoff** |
| Автономный запуск без манифеста и kontext | **Ветка 3: Deep Context** |

---

### Ветка 1: 🚀 Manifest Mode (Вход через Swarm Manifest)

Используй когда пользователь передаёт готовый файл-манифест с промптами (например `DOCUMENTATION_SWARM_MANIFEST.md`).

1. **Прочитай манифест** через `view_file`. Извлеки:
   - Глобальные зависимости (какие файлы ОБЯЗАН прочитать каждый субагент)
   - Глобальные запреты
   - Блоки `PROMPT_NN` (каждый = один субагент)
   - Приоритеты (P0, P1, P2, P3)
2. **Сформируй волны** по приоритетам:
   - Волна 1 = все PROMPT с приоритетом P0 (независимые)
   - Волна 2 = P1 (могут зависеть от P0)
   - Волна 3+ = P2, P3
3. **Собери промпт для каждого субагента** по формуле:
   ```
   ПРОМПТ = Глобальные зависимости + Глобальные запреты + Тело PROMPT_NN
   ```
4. **Запусти Волну 1** ОДНИМ вызовом `invoke_subagent` с массивом `Subagents[]`:
   ```json
   invoke_subagent({
     "Subagents": [
       {"TypeName": "self", "Role": "P0-Agent-1", "Prompt": "...", "Model": "flash"},
       {"TypeName": "self", "Role": "P0-Agent-2", "Prompt": "...", "Model": "flash"},
       {"TypeName": "self", "Role": "P0-Agent-3", "Prompt": "...", "Model": "flash"}
     ]
   })
   ```
5. **Перестань вызывать инструменты** — система разбудит тебя когда агенты ответят.
6. Когда ответы получены → зафиксируй результаты → запусти Волну 2 аналогично.
7. **Финал**: обнови индексные файлы (если указано в манифесте).

**Сразу переходи к запуску** — шаги 1-3 основного пайплайна (контекст, ресёрч, интервью) НЕ НУЖНЫ.

---

### Ветка 2: 🔗 Chained Handoff (Вызов из `session-kontext`)

Если скилл вызван в цепочке завершения сессии из `session-kontext` (или в `kontext/` только что создан свежий файл):

1. ⚡ **SKIP глубокого ресёрча:** ЗАПРЕЩЕНО сканировать проект с нуля.
2. Прочитай свежий kontext-файл (например, `kontext/NN_*.md`) и `card.json` (или `ROADMAP.md`).
3. 📜 **ПРАВИЛО ПЕРВОИСТОЧНИКОВ:** Проверь наличие оригиналов (в `docs/`, ТЗ, PRD). При наличии — ОБЯЗАТЕЛЬНО включи в манифест.
4. Извлеки реестр артефактов из Раздела 1 kontext-файла.
5. Сформируй `ai_manifests/sprint_[N].md` на основе Раздела 7.3 и 7.4.
6. **Переходи к Шагу 3 (Интервью).**

---

### Ветка 3: 🔍 Deep Context (Автономный запуск)

Если скилл запущен пользователем без манифеста:

1. Проверь наличие `_project_card/card.json` или `card.json`.
2. **Если карточки нет:** используй `find_by_name` для `project-architect-extractor`. Если найден — делегируй сборку карты. Если нет — Lite-режим (`package.json`, `ROADMAP.md`, `README.md`).
3. **Если карточка есть:** прочитай через `view_file`, создай `ai_manifests/project_context.md`.
4. 🛑 **ОСТАНОВКА И АППРУВ:** Выведи контекст и переходи к Шагу 2.

---

### Шаг 2: Глубокий ресёрч задачи (Planning Mode)
*В Manifest Mode — ПРОПУСКАЕТСЯ. В Chained Handoff — объединяется с чтением kontext-файла.*

1. Прочитай файлы спринта, в первую очередь **ОРИГИНАЛЬНЫЕ СПЕЦИФИКАЦИИ**.
2. Ресёрч кодовой базы на блокеры (ошибки, зависимости).
3. Создай `ai_manifests/sprint_[N].md` с планом, ссылкой на оригинал и блокерами.

---

### Шаг 3: Глубокое Интерактивное Интервью (через `ask_question`)
*В Manifest Mode — ПРОПУСКАЕТСЯ.*

Проведи "аналитический допрос" пользователя. 3-4 точечных вопроса по 3 векторам:
1. **Образ результата (DoD):** В каком виде нужен финал?
2. **Развилки (Decision Points):** Какие компромиссы выбираем?
3. **Ограничения (Constraints):** Последствия блокеров?

🚫 **Anti-Jargon:** Запрет на "птичий язык". Дай понятные варианты в `ask_question`.

> ⚠️ **ЯКОРЬ ПАМЯТИ:** Ответ пользователя — данные для Шага 4. **СТРОГО ПЕРЕХОДИ К ШАГУ 3.5.** Не начинай программировать!

---

### Шаг 3.5: Построение графа зависимостей (Dependency Graph)

Перед запуском агентов ОБЯЗАТЕЛЬНО построй таблицу графа зависимостей:
`| Задача | Зависит от | Волна |`

**Правило по умолчанию: AGGRESSIVE PARALLEL** — всё параллельно по умолчанию. Последовательно ТОЛЬКО если задача B явно требует выход задачи A как вход.
Если зависимости неясны — спроси пользователя или оркестратора через `ask_question`.
После заполнения таблицы сгруппируй задачи в Волны и переходи к Шагу 4.

---

### Шаг 4: Генерация и ПАРАЛЛЕЛЬНЫЙ запуск роя

#### Режим A: Inline (рекомендуется для ≤5 агентов)
Собери промпты inline и запусти **ОДНИМ вызовом**:

```json
invoke_subagent({
  "Subagents": [
    {
      "TypeName": "self",
      "Role": "Agent 1 — [Роль]",
      "Prompt": "[Полный промпт с контекстом, задачей, ограничениями, форматом вывода]",
      "Model": "flash"
    },
    {
      "TypeName": "self",
      "Role": "Agent 2 — [Роль]",
      "Prompt": "[Полный промпт...]",
      "Model": "flash"
    }
  ]
})
```

#### Режим B: File-Based (для 6+ агентов или повторного использования)
Используй `prompt_generator.py` в `--batch` режиме:

```bash
python "[ПУТЬ_К_СКИЛЛУ]/scripts/prompt_generator.py" \
  --batch "ai_manifests/sprint_agents.json" \
  --project "Project Name" \
  --outdir "scripts/prompts"
```

Затем прочитай сгенерированные файлы через `view_file` и запусти ПАРАЛЛЕЛЬНО.

#### Режим C: CLI по одному (legacy, не рекомендуется)
```bash
python "[ПУТЬ_К_СКИЛЛУ]/scripts/prompt_generator.py" \
  --project "Project Name" \
  --role "Role" \
  --specialization "Spec" \
  --sources "1. file.md\n2. file2.md" \
  --output_format "TypeScript module" \
  --task_steps "1. Read spec\n2. Implement\n3. Test" \
  --model "flash" \
  --outdir "scripts/prompts"
```

### 🚀 КРИТИЧЕСКОЕ ПРАВИЛО ПАРАЛЛЕЛИЗМА

**НЕ запускай агентов по одному** если они независимы!

❌ НЕПРАВИЛЬНО:
```
invoke_subagent(Subagents: [{Role: "Agent 1", ...}])
// ждём...
invoke_subagent(Subagents: [{Role: "Agent 2", ...}])
// ждём...
```

✅ ПРАВИЛЬНО:
```
invoke_subagent(Subagents: [
  {Role: "Agent 1", ...},
  {Role: "Agent 2", ...},
  {Role: "Agent 3", ...}
])
// Все запускаются ОДНОВРЕМЕННО!
// Перестань вызывать инструменты — система разбудит когда придут ответы.
```

### Шаг 5: Вывод результата и интеграция

1. Дождись ответов от ВСЕХ субагентов (Reactive Wakeup).
2. Проведи кросс-валидацию (нет ли противоречий?).
3. Обнови индексные файлы проекта если нужно.
4. 🔗 **CHAINED HANDOFF INTEGRATION:**
   Если вызов шёл из `session-kontext`, передай мастер-промпт для запечатывания в `### 7.1. [SWARM MODE]` kontext-файла. Сообщи:
   *«Рой запущен! [N] агентов работают параллельно. Результаты будут записаны в [пути]. Промпты в `scripts/prompts/`. В новом окне — вызови `/gemini-flash-orchestrator` для продолжения.»*

---

### Изоляция рабочих пространств (Workspace Isolation)

При запуске агентов с `TypeName: "self"` для параллельного кодинга используй параметр `Workspace`:
- `"inherit"` (по умолчанию) — агент работает в общем каталоге. Подходит для последовательных задач.
- `"branch"` — агент получает изолированный git worktree. **РЕКОМЕНДУЕТСЯ для параллельных кодинг-задач** для предотвращения конфликтов записи.
- `"share"` — агент получает общий каталог с возможностью независимого ветвления.

**Single-Writer Rule:** Параллельные агенты НИКОГДА не пишут в один файл. Общие файлы модифицирует только оркестратор.

### Heartbeat / Timeout (Защита от зависания)

После запуска волны субагентов РЕКОМЕНДУЕТСЯ установить таймер:
```
schedule(DurationSeconds=900, Prompt="Проверь субагентов", TimerCondition="any")
```
- Дефолтный таймаут: **15 минут**.
- При истечении — проверь `manage_subagents list`, зависших — `kill`.
- `TimerCondition="any"` автоматически отменяет таймер при получении первого сообщения.
