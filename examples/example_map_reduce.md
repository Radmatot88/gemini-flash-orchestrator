# Пример: Map-Reduce (Scatter-Gather) для массовых задач

## Топология:
Топология Map-Reduce используется для массовой обработки однородных задач (например, аудит большого количества файлов). 
Оркестратор (scatter) разбивает общую задачу на небольшие порции (chunks) и делегирует их параллельным агентам (map). 
После завершения работы всех воркеров, оркестратор вызывает агента-агрегатора (reduce), который собирает все результаты и формирует единый отчёт.

## System Prompt для оркестратора
```markdown
Ты — оркестратор аудита доступности (a11y).
Твоя задача: проверить все 20+ компонентов в директории `src/components/`.

Действуй строго по фазам:
1. SCATTER: Разбей список из 20 файлов на 4 группы по 5 файлов.
2. MAP (Волна 1): Запусти 4 агента `research` параллельно. Передай каждому агенту одну группу из 5 файлов. Агенты должны вернуть результаты аудита в формате BLUF через `send_message`.
3. DEPENDENCY GATE: Дождись ответов от всех 4 агентов.
4. REDUCE (Волна 2): Запусти 1 агента `self`. Передай ему результаты всех 4 агентов (или пути к файлам, если результатов много). Агент должен объединить результаты в один сводный отчёт по доступности и сохранить его в `/scratch/a11y_audit_report.md`.
```

## 📊 ГРАФ ЗАВИСИМОСТЕЙ
| Wave | ID | Parent | DependencyGate | Task |
|---|---|---|---|---|
| 1 | W1_Chunk1 | (none) | (none) | Аудит файлов 1-5 |
| 1 | W1_Chunk2 | (none) | (none) | Аудит файлов 6-10 |
| 1 | W1_Chunk3 | (none) | (none) | Аудит файлов 11-15 |
| 1 | W1_Chunk4 | (none) | (none) | Аудит файлов 16-20 |
| 2 | W2_Reduce | W1_Chunk1, W1_Chunk2, W1_Chunk3, W1_Chunk4 | Wait for ALL Wave 1 | Сбор отчётов и запись в `/scratch/` |

## 🚀 ФАЗА SCATTER (Разбиение на чанки)
Оркестратор группирует 20 файлов в 4 списка:
- Chunk 1: component1..5
- Chunk 2: component6..10
...

## 🗺️ ФАЗА MAP (Волна 1 — Параллельные воркеры)
Запуск параллельных воркеров для обработки каждого чанка:

```json
{

    {

      "Role": "A11y-Chunk1",

    {
      "TypeName": "research",
      "Role": "A11y-Chunk2",
      "Prompt": "Проведи аудит доступности (a11y) следующих файлов: src/components/[6-10]. Верни результат через send_message в формате BLUF Markdown.",
      "Model": "flash"
    },
```

## ⚠️ DEPENDENCY GATE
Оркестратор приостанавливает выполнение новых задач, пока не получит сообщения от всех четырех воркеров (W1_Chunk1, W1_Chunk2, W1_Chunk3, W1_Chunk4).

## 🔻 ФАЗА REDUCE (Волна 2 — Агрегатор)
После получения всех ответов, оркестратор запускает задачу агрегации:

```json
{
  "Subagents": [
    {
      "TypeName": "self",
      "Role": "A11y-Aggregator",
      "Prompt": "Проанализируй следующие отчеты воркеров по аудиту доступности:\n[Вставить текст отчета Chunk1]\n[Вставить текст отчета Chunk2]\n...\nСведи все найденные [ RISK ] и [ BLOCKER ] в один итоговый документ. Сгруппируй по типу проблемы (Keyboard Navigation, Contrast, ARIA). Сохрани итоговый документ в файл /scratch/a11y_audit_report.md.",
      "Model": "flash"
    }
  ]
}
```

## 🚨 ПРАВИЛА
1. **Не жди** результатов первой волны синхронно (то есть в цикле), просто отправь задачу и закончи ход. Dependency Gate реализуется тем, что оркестратор ничего не делает до получения всех ответов.
2. Размер `send_message` воркеров ограничен (<=50 строк). Воркеры должны возвращать BLUF.
3. Агрегатор записывает результат в файл, так как финальный отчет будет большим.
